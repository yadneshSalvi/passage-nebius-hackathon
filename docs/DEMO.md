# Passage: a three-minute evidence walkthrough

Use the prepared local workspace at [127.0.0.1:4101](http://127.0.0.1:4101). With dependencies already installed, `npm run build` and `PASSAGE_ALLOW_LIVE=false npm run demo` serve the product. The walkthrough below uses saved evidence and does not require a model request or a new source build. Saved runs live in the local `.passage/` store; a fresh clone does not include them.

1. **Start at the home page.** Open the featured **TodoMVC: keyboard edit, cancel & save** repair. Explain the task: reach editing by keyboard, discard a cancelled edit, and save an intentional change. This is independently authored public source with a recorded Nebius / NVIDIA Nemotron repair.
2. **Review the contract.** Show the reviewed requirements and their evidence references. The contract was frozen before candidate verification. Review provenance is automated development, with inferred requirements identified separately.
3. **Repair the source.** Inspect the actual patch and retained provider receipts. The original source, failed attempts and source identities remain inspectable. A passing recorded result covers its exact contract and build.
4. **Check & export.** The export panel is at the top of this stage. **Evidence JSON** retains the source manifest, contract, attempts and replays; **Runnable guard** packages the repeatable check. Below it, use **Stored execution** to inspect a recorded result and its browser trace. The source selector controls a future run; it does not change the stored result being displayed.
5. **Return home for the authored case.** **Try the keyboard** opens the actual fictional appointment application. **Reviewed appointment repair** opens the stored temporal workflow, including cancellation and preservation evidence. **Historical 9-check repair** is explicitly the older, narrower verifier result.

The story to leave with: a blocked task becomes a reviewed contract, a bounded source repair, and a regression guard that keeps the same expectations.
