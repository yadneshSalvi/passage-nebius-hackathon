# Journey Compiler: implemented scope and evidence

28 October 2026. This is a new development record. The original evaluation, generated source samples, nine-check receipts and provider ledgers remain unchanged.

Passage now records a bounded task attempt, proposes typed temporal requirements, freezes an explicitly reviewed contract, asks Nemotron to inspect and repair source, and replays that contract independently of the candidate. The same interpreter runs an authored appointment adapter and two unrelated public React source cases. A portable guard checks a later revision without inference or the original database.

This is assisted contract authoring. Task bindings and initial protected requirements are supplied by a developer. Model assertions remain proposals; all reviews in this record are automated development reviews, not maintainer or accessibility-specialist acceptance. No participants were recruited.

## Architecture and boundaries

| Layer | Responsibility and boundary |
| --- | --- |
| `shared/temporal.ts` | Data-only bindings, actions, assertions, dependencies, event vocabulary and execution bounds. There is no model-generated JavaScript test. |
| `engine/trace-recorder.ts` | Actual controller actions, focus/input instrumentation and browser request/response events. Page-origin events retain their lower-trust provenance and cannot forge controller assertions or network receipts. |
| `engine/contract-interpreter.ts` | Validates the immutable approved digest and executes real keyboard actions. Required unexecuted assertions cannot pass. Missing protected observers produce errors. |
| `server/journey-model.ts` | Trace-derived typed assertions; bounded source-file selection; immutable source-line references; scoped patches; bounded public schedule proposals. Repository comments and page text are untrusted data. |
| `server/journey-service.ts` | Authored appointment capture, draft/review, repair, all-three-schedule acceptance, later source revisions, public probes, reduction and export. |
| `server/repository-journey-service.ts` | The same stages for immutable external source. No fixture-family branch is added to the interpreter. Only existing admitted source paths can change. |
| `engine/repository-worker.ts` | Fixed dependency/static React build in a dedicated disposable Linux environment. No repository scripts, dependency selection, host mounts, build network or provider secrets. See [worker details](repository-worker.md). |
| Guard CLIs | Rebuild exact or later source and execute the frozen contract in a fresh session. They require neither provider credentials nor the original SQLite database. |

The authored adapter alone uses the trusted local appointment service. Its cancellation driver holds and releases an actual availability response; it does not invent a successful response or bypass validation. The protected observer reads exact stored date, attendee, source/build identity and record count outside the candidate.

The external static adapter checks rendered application state. A separately registered `RepositoryOutcomeObserver` is required for a business assertion. TodoMVC is in-memory; no persistence or transaction is claimed. The react-modal control makes no form-submission claim. Static builds do not imply support for arbitrary monorepos or backend services.

`inspectRepository` reads regular blobs from a local Git object database at a full commit hash and checks the configured public remote. It verifies local Git bytes, not that an untrusted checkout's commit is present on the public upstream. JSON import verifies internal file/hash integrity only. The distinction is displayed and exported. An early `verifiedUpstreamBytes` label overstated the local check; current views correct it explicitly without changing source/build or execution identities.

The protected component bootstrap and module aliases are part of snapshot identity and cannot be patched. Object-key serialization order is normalized; finite legacy bootstrap ordering identities remain valid so earlier real receipts keep their hashes. Changing the actual adapter requires a new reviewed guard.

## Contract and repair integrity

The typed vocabulary covers value preservation, exact values, focus within a bound element, repeated forward/backward modal containment, closure with trigger focus, and exact protected outcomes. Bounds include generated modal key presses. The runner stops at the first falsified checkpoint; later obligations remain unexecuted. Driver/observer errors are errors, not evidence that a user-facing barrier was repaired.

Final adversarial review reproduced a false focus acceptance when imported JavaScript replaced the main world's `Document.prototype.activeElement`. The hardened interpreter now samples native `:focus` through Playwright's isolated locator world for containment, focus restoration and keyboard-target prerequisites. Four actual browser regressions cover forged focus/prototypes and standard value/visibility observations. New executions carry `verifierVersion: passage-temporal-native-focus-v2`; earlier unversioned evidence remains unchanged. See the [recorded before/after security check](focus-oracle-security-qa-2026-10-28.json). Native focus is still sampled at bounded checkpoints, and page-authored content is not independent semantic or business truth.

The final Nebius TodoMVC candidate and unchanged react-modal control each passed all three frozen checks again with that hardened verifier. A freshly extracted, hash-checked guard passed the same candidate and rejected a deliberate keyboard regression, leaving later checks unexecuted. The [new version's independent automated-development replay record](native-focus-development-qa.json) is separate from the earlier evidence and from actual AT qualification.

A subsequent adversarial check found that a renderer stuck in application JavaScript could hold trace cleanup beyond the contract deadline. The current runtime, `passage-temporal-native-focus-bounded-cleanup-v3`, bounds recorder flush and cleanup, preserves collected evidence, and closes page/context/browser independently with a two-second shutdown cap. A cleanup timeout is an execution error and cannot accept a candidate. [Focused checks](bounded-cleanup-security-qa-2026-10-28.json) cover a real starving renderer, cancellation, healthy recording and repository-service shutdown. An [independent automated-development replay](bounded-cleanup-development-qa.json) again passed both external cases and a freshly extracted guard, and confirmed the starving renderer returned an error around 303 ms. The earlier v2 receipts retain their original version. OS-level forced termination of a browser process that itself refuses to exit is not guaranteed by this API layer.

A separate final check found an exception path in the authored fixture wrapper: operator cancellation during a pending real availability request could make recorder shutdown throw before browser closure, losing the returned cancelled execution and leaving the browser connected. `authored-fixture-temporal-v3` now closes independently, retains cancelled evidence, and bounds cleanup to two seconds. A real pending-request cancellation and a normal protected-outcome control both passed, with disconnected browsers. This [authored wrapper record](authored-cancellation-cleanup-qa-2026-10-28.json) is distinct from the earlier interpreter and external cleanup evidence; the interpreter version itself is unchanged.

A model draft must retain each supplied protected assertion exactly, map every obligation to executable assertions, and cite captured event IDs. A claim labeled observed needs controller or browser-network evidence; page instrumentation alone is insufficient. Inferred requirements can have no event reference when the transition was never reached. Ambiguities remain visible.

Review binds the exact draft and contract digest. Changing a draft clears approval. The repository correction flow can remove an unsupported model addition, but cannot remove the initial protected requirements. Candidate acceptance never edits the contract. Exports exclude old accepted patches when their contract no longer matches, while retaining old drafts, failed calls and repair attempts.

Source inspection selects from the immutable manifest. For the authored adapter's single permitted file, the controller selects that exact hash-checked file deterministically, without a model request or receipt. Inspection records identify this method. External file selection remains model-backed; only supplied paths are allowed and the unused purpose text is advisory. The original external five-call qualification is unchanged.

Current source localization selects short line handles scoped to one immutable inspection. The controller binds each to its path, complete source digest and line number; these handles are not global identifiers. The controller requires a consecutive range from one inspected file, resolves exact bytes and records their hash, with a captured event reference or a separately labeled source-bound observation. Unknown, repeated, reordered, nonconsecutive and cross-file IDs are rejected. The unused localization summary is advisory. Strict exact-quotation validation remains for the prior wire format. Up to three citation attempts can use the exact public diagnostic and reference catalog; a capture ID is not an individual event ID. Source matching does not prove the model's causal explanation.

Supplemental observations can describe a regression outside the frozen suite. Each has the exact source digest, observer, supplied provenance and recording time; it is not converted into captured trace evidence or independent review. Localization and patching receive those current-source observations explicitly. `reportedObservationRefs` stays separate from captured-event `evidenceRefs`, and stale or unknown references reject before patching. Passing the frozen checks does not resolve a supplemental report.

The patch stage can only change inspected existing paths with matching before hashes. Retry starts from the last nonempty candidate, retains earlier changed files, and supplies actual source-admission errors even when a rejected candidate never reached verification. Contract event IDs refer to trusted adapter drivers; they are not DOM events for the patch to invent. Cumulative external diffs are against the original source.

When executions exist for the exact inspected source, retry context selects those current-source checks and traces without prepending the stale original failures. If an admission-rejected revision has never executed, its latest predecessor's traces are explicitly labeled as earlier-revision behavior. All earlier executions and failures remain stored and exported. Multi-file selection gets a bounded trace tail plus complete checks; full selected capture context is available to localization.

When the inspected authored source fails admission, the controller includes a fresh bounded diagnostic bound to that source hash and asks for minimal capability/syntax correction first. Actual browser behavior is checked only after admission. The guard documents exact allowed local-ref query syntax and rejected callsites; its policy is unchanged. Rejected source, schema errors, citation failures and subsequent corrections stay in the repair history.

Rejected raw-source output has its own artifact and module digests. Retry feedback may include twelve bounded numbered lines around its actual parser location and a read-only reparse diagnostic, explicitly labeled as never executed and distinct from the currently inspected source. This makes duplicate-declaration errors actionable without rewriting or treating rejected bytes as an admitted patch.

The one-file authored adapter uses `passage-journey-source-v2-supplied-observations` on prompt-schema routes; earlier v1 calls retain their original receipts. A strict final-content parser accepts one complete raw JSX module or one exact code fence; the controller supplies its immutable path and before hash. Source parsing, size limits, the unchanged AST admission guard and all frozen temporal checks still apply. The model supplies the actual source; this is not a handcrafted fallback. Localization remains model-backed JSON. Multi-file external patches and providers that require JSON retain the existing structured protocol. New receipts explicitly record the output protocol, while historical malformed JSON and source rejections remain in the denominator.

Public exploration asks the model for one order/subset of approved action IDs, using at most the latest capture of that exact source and selected schedule. The compiler rejects invented commands, duplicate actions, missing required actions and dependency violations. Execution still belongs to the browser and trusted event driver. A reducer deletes optional groups, chunks, pairs or individual actions only when a fresh run reproduces the same contract-bound failure signature. Required actions, dependencies and checkpoint obligations cannot be removed. The 24-replay budget is unchanged; exhaustion or inconclusive executions cannot establish local minimality, and global minimality is never claimed. This is bounded development exploration, not exhaustive testing or a hidden evaluator.

Each reduction has an immutable start, per-replay evidence and completed or errored result in the exported history. The counterexample in the UI is only the latest completed view. Earlier counts-only reductions are preserved with an explicit missing-trial-trace limitation and unknown original reduction timestamp; their rejected trials are not reconstructed. Cancellation retains completed trial evidence before ending the run, and errored runs remain counted in the visible history.

The real authored attempt-22 cancellation failure demonstrated the grouping change. Its earlier single-deletion run retained ten actions after two unsuccessful replays. A new grouped run removed the optional forward/backward pair together in one actual replay, retaining the identical source, frozen contract and late-response failure signature with eight actions. Both runs remain separate, including the old counts-only limitation. [Independent history/export QA](grouped-reduction-development-qa.json) verifies their identities, retained replay and bounded-minimality wording.

## Assistive evidence and human-ready workflow

Actual Orca speech and keyboard observations are bound to source, build, session, timestamps, browser/AT versions and raw-content hashes. The UI keeps these apart from browser focus traces and human participation. Imported receipts are operator-attested, not cryptographically authenticated execution. They cannot raise participant counts or claim independent review/backend success.

The Linux configuration needs a disclosed local Guidepup asset compatibility mapping; upstream 0.36.2 listed Linux 7 while the available Colima kernel is Linux 6.8. Every setup/startup failure and later diagnostic configuration is retained. See the [runner protocol and stability evidence](actual-screen-reader.md) for the current exact image and series. No result from another configuration is silently pooled into a reliability percentage.

The final pinned v3 setup completed twenty of twenty fresh candidate captures with actual speech and cancelled-value preservation. A same-image, same-protocol original control remained keyboard blocked. V1's eighteen captures of twenty, v2 diagnostics and the diagnosed v2 startup failure remain separate. The [audited series](actual-at-qualification-2026-10-28.json) retains every identity/hash; the [raw before](upgrade-evidence/todomvc-nebius.at-original-control.json) and [raw after](upgrade-evidence/todomvc-nebius.at-run-01.json) are also attached in the final Nebius repository workspace. This establishes the reported local configuration's observations, not population reliability or participant benefit.

The participant workflow creates a new protected attempt before a person acts. Exact intended fields and source/build identity are then checked against that attempt's stored outcome, not a verifier-created booking. Review requires a separately named reviewer and explicit attestation. Local names do not authenticate identity or independence. Consent, private-content hashes, expiry and deletion remain enforced. With no available participants or independent reviewers, those gates remain pending.
